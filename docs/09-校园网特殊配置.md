# 校园网特殊配置（可选）

> 这一篇只针对**在校园网里用**的情况。家里/热点用不到，可以跳过。
>
> 依据：一份覆盖多个教学楼、Windows 与 macOS 双端实测的校园网调查报告
> （DNS 收口/投毒、SNI 封锁、CF 网段拉黑、带宽与抖动）。

---

## 一、先说结论

**这套方案天然免疫其中 90% 的限制**，因为它的设计恰好绕开了被封的那几层：

| 校园网的做法 | 我们为什么不受影响 |
|---|---|
| 封掉外部 UDP 53，只留校内 DNS | 客户端**不需要 DoH 自举**：服务器写的是 IP，不查域名 |
| DNS 投毒（youtube→Facebook IP 之类） | 墙外域名**不本地解析**，原样交给服务器解析 |
| 按 SNI 封锁（youtube / steam / 4399 / 抖音） | 线上跑的是 TLS 到 `www.microsoft.com`，**你的真实 SNI 在加密层内部** |
| 按 IP 段拉黑 Cloudflare（104.21 / 172.67…） | 我们连的是自己的 AWS IP，不经过那些段 |
| 对称 NAT、无 IPv6 | 只走 TCP 443，**不需要打洞、不需要 IPv6** |
| 机场"36 个节点全 Error" | 那个故障的根因是 DoH 自举死锁，我们根本不走那条路 |

实测（同一台校园网机器，用本文档的客户端）：

```
TCP 443          5/5 可达
google           204 / 0.30s
github           200 / 0.61s
吞吐             5.19 MB/s（约 41 Mbps）
20 次连续请求    20/20
```

## 二、需要补的两处（否则会有"网页能开、抖音打不开"的怪现象）

### ① 直连出站必须只用 IPv4

校园网没有 IPv6，但域名经常返回 AAAA 记录。默认情况下客户端会尝试 IPv6，
结果**挂到超时**——表现是"某些国内站明明没被墙，却打不开"。

修法：在 `config.json` 的 `direct` 出站上加一行：

```json
{ "tag": "direct", "protocol": "freedom", "domainStrategy": "UseIPv4" }
```

> 实测对比：加之前 `douyin.com` 经代理 000 / 15 秒；加之后 200 / 0.16 秒。

### ② 被 SNI 封的**国内**域名要指到代理

这是最反直觉的一条：抖音、4399 是**国内站**，但校园网在 SNI 层把它们拦了
（同一 IP，SNI 写 `microsoft.com` 能握手，写 `www.douyin.com` 直接静默丢包）。

而我们的分流规则是"国内域名走直连"——所以它们会被判成直连 → 照样打不开。

修法：在 `routing.rules` 里，**把这几条放在 `geosite:cn` 之前**：

```json
{
  "type": "field",
  "domain": [
    "domain:douyin.com", "domain:douyinvod.com", "domain:douyinpic.com",
    "domain:douyinstatic.com", "domain:douyincdn.com", "domain:iesdouyin.com",
    "domain:amemv.com", "domain:snssdk.com", "domain:byteimg.com",
    "domain:bytedance.com", "domain:pstatp.com", "domain:zjcdn.com",
    "domain:4399.com"
  ],
  "outboundTag": "proxy"
}
```

> **抖音不是一个域名，是 12 个。** 只加 `douyin.com` 没用——视频走的是
> `douyinvod.com` 这类独立的 CDN 域名，它们同样被拦。

实测（强制走代理）：

```
www.douyin.com        200 / 0.91s
v3-web.douyinvod.com  403 / 0.73s   ← 403 = 可达（CDN 根路径的正常响应）
www.4399.com          200 / 1.04s
```

**代价**：抖音的视频要走境外流量。按 720p 估算每小时几百 MB，
2TB/月的套餐够用，但别整天挂着刷。

## 三、这套方案解决不了的

诚实地说清楚，免得同学抱错期待：

**① 国服游戏联机**

游戏走的是自己的 UDP socket，不认系统代理；开 TUN 又会把国服绕出国
（延迟 +150ms 起，还可能触发风控）。**这是加速器的活，不是代理的活。**

好消息是：我们的方案**不会破坏游戏**——没有 TUN，游戏流量原样直连，和没装一样。

**② 校园网的带宽上限与抖动**

调查里记的 8.6–25 Mbps、丢包 8%、抖动 stddev 65ms，都是**接入层**的问题。
代理不能变快，只能在原来的链路上多走一跳东京（约 +40ms）。

**③ 单 IP 就是单点**

学校已经在按段拉黑（Cloudflare 若干段）。哪天你的 IP 被点名，换一个弹性 IP 就行——
几分钟的事，这是自建相对机场唯一但足够重要的优势。

**④ 流量特征仍然可见**

对方能看到"这台机器在持续和某个境外 IP 通信"。我们改变的是**内容与协议特征**，
不是元数据。这一点必须说清楚。

## 四、怎么确认某个站是"被 SNI 拦"还是"根本打不开"

在校园网里，关掉代理，执行：

```bash
# 用它的真实 IP，分别用两个 SNI 握手
openssl s_client -connect <真实IP>:443 -servername www.douyin.com  </dev/null 2>&1 | head -3
openssl s_client -connect <真实IP>:443 -servername www.microsoft.com </dev/null 2>&1 | head -3
```

- 第一个挂住、第二个 `Verify return code: 0` → **按 SNI 拦的**，把域名加进上面的列表
- 两个都通 → 不是 SNI 问题，先查 DNS 和本地客户端
- 两个都挂 → 按 IP 封的，只能走代理，但可能需要换机房

## 五、排查顺序（校园网版）

```
1. 443 通不通        Test-NetConnection / nc -vz      → 不通 = IP 被拉黑，换 IP
2. 本地在跑吗        netstat -ano | findstr 10809
3. 系统代理设了吗    设置 → 网络 → 代理
4. 浏览器重开过吗    完全退出再打开（不是刷新）
5. 某个国内站打不开  用第四节的 openssl 判定，加规则
6. 某个国外站打不开  看是不是该走代理（`curl -x` 测一下）
7. 全都慢            先测本地网速，再怀疑线路（接入层带宽）
```

## 六、如果哪天一觉醒来"全都打不通"

上面五节解决的是"部分网站打不开"。还有一种更狠的情况：

**昨天一切正常，今天连服务器都连不上，所有境外网站全部超时。**

这不是配置坏了，是**你的服务器 IP 被学校拉黑了**（我们实测过：同一个 IP 只活了 1 天）。

判断方法（3 分钟）：

```bash
Test-NetConnection 203.0.113.45 -Port 443   # 超时
Test-NetConnection github.com -Port 443     # 正常
```

第一行超时、第二行正常 = **IP 被封**。

修法是用 Cloudflare 前置绕过去，完整步骤在下一篇：

👉 **[10-学校封了服务器IP怎么办](10-学校封了服务器IP怎么办.md)**

那篇里还有"双出口自动切换"的配置：直连和 Cloudflare 两条都挂着，
客户端每 30 秒测一次，哪条通用哪条，你不用手动换。
