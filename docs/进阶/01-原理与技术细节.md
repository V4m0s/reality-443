# 原理：为什么 443 + REALITY 能伪装成正常 HTTPS

读这一节你不需要会写代码，只需要知道三件事：
**TLS 握手长什么样**、**SNI 是怎么暴露的**、**REALITY 怎么把"没有密钥的人"骗过去**。

---

## 1. 一次普通的 HTTPS 访问

你打开 `https://www.microsoft.com`，网络上实际发生的是：

```
客户端                                    服务器
  │  ── TCP 三次握手 ───────────────────►  │
  │  ◄──────────────────────────────────  │
  │                                        │
  │  ── ClientHello ────────────────────►  │   ← 明文！里面有 SNI = "www.microsoft.com"
  │  ◄──────────────── ServerHello ──────  │
  │  ◄──────────────── Certificate ──────  │   ← 证书链，能被中间人看到
  │  ── Finished ───────────────────────►  │
  │                                        │
  │  ══ 加密的应用数据 ═══════════════════►  │
```

两个关键事实：

1. **ClientHello 是明文的**。中间设备能看到你要访问的域名（SNI 字段）。
   这就是为什么"按域名封锁"很容易实现。
2. **TLS 握手有指纹**。不同客户端（Chrome、Firefox、Go 的 crypto/tls）发的
   ClientHello 在扩展顺序、加密套件列表、GREASE 值上都不一样。
   一个"长得不像浏览器"的握手，即使内容是加密的，也能被识别出来。

---

## 2. 常见代理方案的三种暴露面

| 方案 | 中间人能看到什么 | 弱点 |
|---|---|---|
| 明文 HTTP 代理 | 目标域名、内容 | 全裸 |
| Shadowsocks | 无域名，随机字节流 | 流量特征不像任何正常协议，可被识别 |
| Trojan（自有域名 + 真证书） | SNI = 你的域名 | 你的域名没有"值得访问"的声誉；证书签发记录可查 |
| **VLESS + REALITY** | **SNI = 大站域名，证书 = 该大站的真证书** | 需要对端支持 REALITY |

核心差别在于：**前者是"伪装成一个网站"，后者是"真的调用了一个真实网站"**。

---

## 3. REALITY 的做法

服务端配置里有一个字段 `dest`：

```json
"realitySettings": {
  "dest": "www.microsoft.com:443",
  "serverNames": ["www.microsoft.com"],
  "privateKey": "...",
  "shortIds": ["..."]
}
```

它的逻辑是：

```
客户端带着 REALITY 认证信息来
        │
        ├── 认证通过 ──► 服务端解密，开始代理
        │
        └── 认证失败 ──► 服务端把这条 TCP **原样转发给 www.microsoft.com**
                         （包括握手、证书、响应）
```

所以对**任何扫描器或中间设备**来说：

- 握手成功、证书是微软的、HTTP/2 正常、响应是微软的页面
- 它无法区分"这是一个真访问微软的用户"和"这是一个代理客户端"

**没有密钥的人拿不到任何异常信号**——他得到的是一个完整、合法的 HTTPS 会话。

这就是 REALITY 与"自签证书 + 域名伪装"的本质区别：后者能被证书链识破，
前者在密码学层面没有可观测的差异。

---

## 4. 为什么必须是 443

- 443 是 HTTPS 的默认端口，封它等于封掉整个互联网
- 高端口（20000+）的 TLS 握手在很多校园网/企业网里会被**概率性丢弃**，实测成功率可以低到 0/8
- 443 上的流量与"正常上网"混在一起，无法按端口做区分

自建的第一个收益就是把"可用性"从概率变成确定：

| 指标 | 机场高端口节点 | 自建 443 |
|---|---|---|
| TLS 握手成功率（受限网络实测） | 0/8 ~ 3/8 | 8/8 |
| 延迟 | 取决于中转 | 取决于你选的机房 |

## 5. 数据流全景

```
 应用 ──► 本地客户端 (10809/10808)
              │  按规则判断：geoip:cn → 直连
              │              其余    → 代理
              ▼
        TLS 1.3 + REALITY 伪装握手
              │  SNI = www.microsoft.com
              ▼
        VPS:443  ──认证通过──► 转发到真实目标
                 └─认证失败──► 回落到 www.microsoft.com
```

客户端侧的**分流**同样重要：国内流量不走代理，否则看视频、打游戏都会绕一圈境外。
配置方法见 [03-客户端-Windows.md](03-Windows技术配置.md)。

---

## 6. 它不解决什么

- **不能隐藏"你在连一个境外 IP"这件事**：目的地 IP 仍然是你的 VPS。本文只处理
  "内容与协议特征"层面的可识别性。
- **不能替代合规**：技术中立，用途自负。
- **共享出口会把风险放大**：一个 IP 上挂几十个人，任何一个人的滥用都会连累整台机器。
