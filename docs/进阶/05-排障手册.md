# 排障：12 个真实故障的症状 → 原因 → 处理

按"从外到内"的顺序排查：**端口能不能连 → 握手像不像 HTTPS → 客户端认不认证 → 应用走不走代理**。

---

## 速查表

| # | 症状 | 最可能的原因 |
|---|---|---|
| 1 | 443 完全连不上（超时） | 云安全组没放行 / 服务没起 |
| 2 | 443 连上了但立刻断 | 服务崩溃，看 journalctl |
| 3 | `REALITY authentication failed` | 客户端版本与密钥不匹配 |
| 4 | `received real certificate (potential MITM)` | 服务端把客户端当普通 TLS，判为未授权 |
| 5 | `config.json` 只有 3 字节 / 内容是 `{}` | 安装脚本中途被 SIGPIPE 打断 |
| 6 | 换二进制报 `Text file busy` | 服务在运行，文件被占用 |
| 7 | TLS 握手成功，但客户端连不上网 | 客户端 config 里 UUID/公钥/shortId 写错 |
| 8 | 客户端连上了，浏览器打不开 | 系统代理没设 / 浏览器用了旧设置 |
| 9 | 命令行能用，浏览器不能用 | 系统代理与环境变量没同步 |
| 10 | 国内站点变慢 | 分流规则缺失或写成了全局 |
| 11 | 一切正常但 ChatGPT 403 | Cloudflare 按 IP 信誉判定 |
| 12 | 昨天好的今天不通 | IP 被墙 → 换弹性 IP，不要重装 |

## 1. 443 完全连不上

```bash
# 云安全组之外，先看服务端有没有在听
sudo ss -ltnp | grep 443
sudo systemctl status xray --no-pager
```

- 服务没起 → `sudo journalctl -u xray -n 50 --no-pager` 看报错
- 服务在听但仍连不上 → **云厂商安全组**（AWS Lightsail：Networking → IPv4 Firewall → 加 TCP 443）
- 系统防火墙也放行一次：`sudo ufw allow 443/tcp`

**两层都要开**，只开一层是最常见的"连不上"。

---

## 2. 配置只有 3 字节（`{}`）

这是安装脚本被 **SIGPIPE** 静默打断的典型症状：

```bash
# 现象：Xray 装好了、systemd 显示 active，但 443 没监听、配置是空的
sudo stat -c '%s bytes' /usr/local/etc/xray/config.json
# 3 bytes
```

原因：脚本里有 `xray version | head -1`。`head` 读够一行就关闭管道，`xray` 收到 SIGPIPE
退出码 141，而 `set -euo pipefail` 把它当失败 → 脚本静默终止，后面的写配置步骤没执行。

处理：

```bash
# 1. 手动把配置补齐，或重跑修好的脚本
# 2. 脚本里所有 | head 后面都要加 || true
xray version 2>/dev/null | head -1 || true
```

判断脚本是否跑完整：**末尾必须打印 UUID / 公钥 / shortId 三项**。

## 3. `REALITY authentication failed`

客户端与服务端的 REALITY 实现不兼容，**或者密钥不对**。

先验证密钥是否配对（在服务端）：

```bash
P=$(sudo python3 -c "import json;print(json.load(open('/usr/local/etc/xray/config.json'))['inbounds'][0]['streamSettings']['realitySettings']['privateKey'])")
xray x25519 -i "$P"          # 输出的 Public key 必须逐字符等于客户端里的 publicKey
```

如果密钥一致，就是版本问题：

| 组合 | 结果 |
|---|---|
| Xray 26 服务端 + Xray 26 客户端 | ✅ |
| Xray 26 服务端 + mihomo 1.10 / 1.19 | ❌ 本错误 |
| Xray 1.8.24 服务端 + Xray 26 生成的密钥 | ❌ `received real certificate` |

**规则：服务端和客户端用同一版本族；密钥必须由将要运行的那个二进制生成。**
降级服务端后，要用降级后的 `xray x25519` 重新生成公私钥并同步客户端。

---

## 4. `received real certificate (potential MITM)`

客户端拿到了**伪装站的真实证书**——说明服务端没有认出你，按"未授权访问"回落到 `dest` 了。

常见原因：

- `publicKey` 与服务端 `privateKey` 不配对（含大小写、少一位）
- `shortId` 不一致
- `serverName` 与服务端 `serverNames` 不同
- 密钥跨版本生成（见上一条）

这不是"被中间人攻击"，是回落机制在工作。**回落能被触发，恰好说明伪装是有效的**。

---

## 5. `Text file busy`

替换正在运行的二进制时会这样：

```bash
sudo systemctl stop xray
sudo cp new-xray /usr/local/bin/xray
sudo chmod +x /usr/local/bin/xray
sudo systemctl start xray
```

## 6. 客户端连上了但打不开网页

按顺序查：

```powershell
# ① 代理进程在不在
tasklist /FI "IMAGENAME eq xray.exe"

# ② 端口在不在听
netstat -ano | findstr 10809

# ③ 绕过代理直连测试（排除代理层）
curl.exe -s -o NUL -w "%{http_code}" --noproxy "*" https://www.baidu.com

# ④ 经代理测试
curl.exe -s -o NUL -w "%{http_code}" -x http://127.0.0.1:10809 https://www.google.com/generate_204
```

- ③ 通、④ 不通 → 代理配置错（UUID/公钥/SNI）
- ③④ 都通、浏览器不通 → 系统代理没设，或**浏览器是启动时读的旧设置** → 完全退出浏览器再开

---

## 7. 浏览器的代理设置

Windows 的代理是**每用户**的注册表值：

```
HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings
    ProxyEnable = 1
    ProxyServer = 127.0.0.1:10809
```

换用户登录后不继承，需要在新账户下再设一次（或用 docs/03 里的 Startup VBS）。

已经开着的浏览器**不会重新读取**代理设置——它启动时读一次。所以改完设置必须重启浏览器，
不是刷新页面。

---

## 8. 命令行能用，浏览器不能用

两套机制：

| 机制 | 谁在用 |
|---|---|
| 注册表 `ProxyEnable/ProxyServer` | 浏览器、系统组件、部分应用 |
| 环境变量 `HTTP_PROXY/HTTPS_PROXY` | Python、curl、git、pip、npm |

只设了其中一个，另一半就不生效。两边都要设（docs/03 第 5 节）。

## 9. 国内站点变慢

检查客户端 `routing` 是否包含：

```json
{ "type": "field", "domain": ["geosite:cn"], "outboundTag": "direct" },
{ "type": "field", "ip": ["geoip:cn"], "outboundTag": "direct" }
```

验证方式（同一文件，直连 vs 经代理）：

```bash
curl -s -o /dev/null -w "直连 %{speed_download}\n" --noproxy "*" https://mirrors.huaweicloud.com/<大文件>
curl -s -o /dev/null -w "代理 %{speed_download}\n" -x http://127.0.0.1:10809 https://mirrors.huaweicloud.com/<大文件>
```

两者应当接近。若代理明显更慢，说明该域名没被 `geosite:cn` 覆盖，手动加一条：

```json
{ "type": "field", "domain": ["domain:example.com"], "outboundTag": "direct" }
```

## 10. ChatGPT 返回 403

Cloudflare 按 **IP 信誉**判定，与配置无关：

- 机房 IP 被标记 → 403 或人机验证
- 香港区域 → 大概率 403
- 东京/新加坡/美西 → 通常正常

处理：换区域或换弹性 IP，不要改客户端配置。

---

## 11. IP 被墙

表现：昨天一切正常，今天 443 直接超时，但服务端 `systemctl status` 正常、`ss` 也在听。

```bash
# 从另一台机器（境外）测
nc -vz <IP> 443
```

- 境外能连、你这边不能 → **IP 被墙了**
- 处理：云控制台**换一个弹性 IP**，几分钟的事；不要重装系统

## 12. 排查顺序（记住这个）

```
① 服务端活着吗      ss -ltnp | grep 443 / systemctl status xray
② 端口通吗          nc -vz IP 443（从外部）
③ 握手像 HTTPS 吗   openssl s_client -connect IP:443 -servername <SNI>
④ 客户端认证过吗    看客户端日志：auth failed / received real certificate
⑤ 本地代理在吗      netstat -ano | findstr 10809
⑥ 应用走代理吗      浏览器重启 / 检查注册表与环境变量
⑦ 分流对吗          国内站直连测速 vs 代理测速
```

**每一步只回答一个问题**，不要跳步——跳步是"越修越乱"的主要原因。
