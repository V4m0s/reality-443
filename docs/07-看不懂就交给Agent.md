# 看不懂？把仓库丢给 AI 就行

> 这不是偷懒，这是**最省时间的做法**。
> 你不需要看懂任何一句技术内容，AI 可以替你看。

---

## 为什么这样可行

这套文档里所有操作都是**确定性的**：点哪里、填什么、敲什么命令，都有唯一正确答案。
AI 最擅长的就是这种"按已知步骤带人做事"。

它还能做三件你自己做不了的事：

1. **看懂报错**：你把截图发它，它知道那行红字是什么意思
2. **按你的水平调整**：你说"我什么都不懂"，它就会拆得更碎
3. **替你检查**：把你的 config.json 贴给它，它能逐字比对哪里填错了

---

## 三种投喂方式

**方式一：给链接（最省事）**

把 GitHub 仓库地址直接发它：

```
https://github.com/你的用户名/reality-443
```

大多数 AI 能直接读网页。

**方式二：给文件**

把这个仓库压缩成 zip，作为附件发给它（豆包、Hermes、ChatGPT 都支持传文件）。

**方式三：只贴一篇**

如果你只卡在某一步，把那一篇的内容复制给它就行，不用给全部。

---

## 直接复制这段提示词

```
我想自己搭一条网络线路，仓库在这里：<贴地址或附件>

我的情况：
- 我完全不懂技术，只会双击和复制粘贴
- 我用的是 Windows <版本>，服务器打算用 AWS Lightsail
- 我每天能花 30 分钟

请你这样带我：
1. 一次只给我一个操作，做完我回复"好了"，你再给下一个
2. 每个操作都要告诉我：点哪里、填什么、正常会看到什么
3. 我发报错截图给你时，先用一句人话解释它是什么意思，再给解决办法
4. 如果我要填参数（IP、UUID 之类），告诉我从哪一段复制、粘到哪一行
5. 全部做完后，带我做一次验收：打开 ipify.org 看 IP、打开 B 站看速度

现在开始第一步。
```

---

## 配合技巧（很关键）

**① 一次只做一步**

如果它一次给你五条命令，回它："太多了，一条一条来。"

**② 报错就截图**

不要自己概括，直接截图。AI 能看到图里的具体字符，你复述反而会丢信息。

**③ 让它先解释再动手**

养成这个习惯：

```
先告诉我这条命令会做什么，我确认了再执行。
```

这样你不会在自己不知道的情况下改坏系统设置。

**④ 卡住超过 10 分钟就换问法**

不要说"不行"，要说清楚：

```
我执行了 X，期望看到 Y，实际看到 Z。
```

---

## ⚠️ 三条安全提醒

**1. 不要把 `.pem` 密钥文件发给任何在线 AI**

那是你服务器的钥匙。需要它帮你看的时候，只说"权限报错了"，不要贴文件内容。

**2. UUID / publicKey / shortId 可以发，但别发到公开地方**

发给 AI 让它检查参数没问题（它们是这条线路的凭据，不是服务器控制权）。
但不要发到群里、论坛、公开的 issue 里。

**3. AI 不能替你做的三件事**

- 注册 AWS（要邮箱验证和信用卡）
- 付款
- 在你电脑上点鼠标

这三件事必须你自己来，其余都能让它带。

---

## 做完之后的验收清单

让 AI 陪你确认这五条：

```
帮我确认五件事：
1. 服务端在跑：sudo ss -ltnp | grep 443 有没有 xray
2. 端口通：Test-NetConnection <IP> -Port 443 是不是 True
3. 本地程序在跑：netstat -ano | findstr 10809 有没有输出
4. 出口对不对：浏览器打开 ipify.org 显示的 IP 是不是我的 VPS
5. 国内没受影响：打开 bilibili.com 能不能正常播放

五条都过了就算完成。
```

---

## 如果 AI 也搞不定

把这段发给它：

```
你已经带我试了几轮还是不行。请换一个思路：
先不要修，我们从头做一次最小验证——
1. 让我在服务器上确认 xray 进程和 443 端口
2. 让我在你指定的位置只测一件事
3. 每一步给我一个明确的"成功长什么样"

如果还是不行，请告诉我这个方案在我的网络环境下可能不成立，以及下一步该换什么方案。
```

诚实地说：**这条线路在极少数网络环境下确实走不通**（比如连 443 都被严格限制）。
那时候换方案比继续修更划算。
