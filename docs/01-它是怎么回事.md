# 它是怎么回事（用快递讲清楚）

> 这一篇没有一句代码，全是比喻。
> 读完你就能跟别人解释：为什么有些线路会被拦、为什么这条不容易被拦。

---

## 先看一个普通的网页请求

你打开 `https://www.microsoft.com`，本质上是在**寄一个包裹**：

```
你  ──►  一个信封  ──►  microsoft.com 的服务器
```

这个信封有两个部分：

- **信封外面**：写着收件人地址（`www.microsoft.com`），**谁都能看到**
- **信封里面**：你真正想说的话，**被封死了，只有收件人能拆开**

这就是 HTTPS。技术上，外面的地址叫 **SNI**，封死的信纸叫 **TLS 加密**。

**关键点：地址是明文的。** 中间任何一台设备都能看到你要寄给谁，只是看不到内容。

---

## 那为什么有些线路会被拦？

因为中间那台设备（可以理解成"邮局安检"）会看三样东西：

**① 收件地址**

如果地址在一个"黑名单"上，直接扣下。

**② 走的是哪个通道**

正常信件走 443 号通道（邮政的主干道）。如果你走的是 20129、33585 这种奇怪的小门，
安检会格外注意——因为正常人不会从那里寄信。

**③ 信封长得像不像正常信封**

不同软件寄信时，信封的折法是不一样的（技术上叫 **TLS 指纹**）。
如果你用的是个"没人见过的折法"，一看就不是普通用户在寄东西。

---

## 机场为什么时好时坏

机场是**很多人共用一批信封和通道**：

- 用的人多 → 地址和通道被盯上 → 一起被扣
- 机场换一批新通道 → 过几天又被盯上
- 你什么都做不了，只能等它换

这就是"今天能用、明天不能用、换节点也没用"的根本原因。**东西不在你手里。**

---

## 我们的做法：把包裹塞进一个普通信封

关键有三步：

**第一步：只用 443 号通道**

这是邮政主干道，封了它等于封掉整个互联网的网页访问，所以没人会封。

**第二步：信封上写一个"正常大公司"的地址**

我们写 `www.microsoft.com`——一个谁都会访问的地址，安检没有理由扣。

**第三步（最关键）：这个包裹真的能寄到微软**

这不是"假地址"。我们租的那台服务器，在**没有正确钥匙的人来敲门时，
会把这个人原样转交给微软的服务器**——连握手、证书、网页内容都转发过去。

所以安检拆开检查时看到的是：

```
✓ 地址：www.microsoft.com（合法）
✓ 证书：微软的真证书（合法）
✓ 内容：微软的网页（合法）
✓ 通道：443（主干道）
```

**它找不到任何异常。** 这就是为什么这条线路能活下来——不是因为它藏得好，
是因为它**真的长得一模一样**。

只有拿着正确钥匙的人（你自己），包裹才会被送到"我们真正想去的地方"。

---

## 为什么国内网站不受影响

我们在客户端加了一个"分拣规则"，逻辑非常简单：

```
看收件地址：
  地址在国内  →  本地投递（和没装一模一样，不多走一公里）
  地址在国外  →  走我们的专线
```

所以：

- 刷 B 站、看爱奇艺、打国服游戏 → **本地直连，速度一点不减**
- 上 GitHub、ChatGPT、Google → 走东京的线路

实测数据：同一个国内文件，直连 2.02 MB/s，走代理 1.71 MB/s——基本没差别，
因为国内流量根本没出国。

---

## 一句话总结

> **别人封的是"可疑的包裹"，我们寄的是"看起来完全正常的包裹"，而且它真的能寄到。**

---

## 常见误解

**Q：需要买域名吗？**
不需要。域名的作用是"让地址看起来合法"，而我们借用了微软的地址。

**Q：需要买证书吗？**
不需要。证书也是借的——用的是微软真的那张。

**Q：这是 VPN 吗？**
严格说不是。VPN 是把整台设备接入另一个网络；这个只是把"出国的部分"转发出去，
国内部分原样直连。对使用者来说效果类似，但更省流量、不影响国内速度。

**Q：那它会不会被封？**
会。如果这台服务器的 IP 被重点盯上，一样会不通。但**你能自己换 IP**——
几分钟的事，这就是自建和机场最大的区别。

**Q：为什么不能给全班同学一起用？**
技术上可以，但一台机器几十个人共用，任何一个人乱来（爬虫、发垃圾信息），
这个 IP 就会被标脏，所有人一起挂。而且流量费用不可控、责任也说不清。
文档里不教这种用法。
